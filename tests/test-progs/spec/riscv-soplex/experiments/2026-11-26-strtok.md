# SoPlex 数据行解析中的 glibc `strtok` 寄存器保护开销

2026-11-26，在单线程 RV64 Linux SE、`v5_full` O3 上运行 SPEC CPU2006 SoPlex 的 `-m10000 test.mps`。对数据行的 9,596 次 `strtok` 调用，硬件门相对同策略软件门平均节省 **49.17 周期/次（11.55%）**。全部调用均有收益，中位数为 50 周期，范围为 45–62 周期。完整程序节省 **449,590 周期（1.19%）**。节省比例均以对应范围的软件门周期为分母。[统计汇总](2026-11-26-strtok-summary.json)

## 调用点与功能

普通版共调用 glibc `strtok` 9,608 次。`MPSInput::readLine` 的五个数据行调用点占 9,596 次，包括 2,174 次传入新行、7,422 次传入 NULL 继续分词。其余 12 次来自两个区段头调用点，在两种保护版中均沿用普通 glibc。[普通版计数](../count_strtok.py)

两种门都将 256 字节的行缓冲区按 8 字节对齐，授权 B 原地写入字符串结束符，返回的 token 指针仍指向 A 的行缓冲区。B 使用真实的 glibc `strtok`、独立栈和持久游标。每次返回时，门撤销 B 的数据授权；下一次传入 NULL 时，B 从自己的游标取回上次的切分位置。[行缓冲区与调用点](../protected/prepare_sources.py) · [B 的 glibc 实现](../protected/prepare_body.py) · [调用门](../protected/gate.S)

短输入覆盖首调、连续取词、返回 NULL 和切换新行，软件门与硬件门均完成 15 次过门并得到最优值 7。完整功能回归在每次返回后核对 token 在原行中的偏移、NULL 结果，以及整行至原始结束符的字节内容。两版的 9,596 条调用记录逐项一致。[逐次校验](../protected/verify_tokens.c)

## 周期测量

软件门和硬件门都保存并恢复 `s0–s11/fs0–fs11`，清零 `t0–t6/ft0–ft6`。计时版的五个调用点直接进入门，移除了客体内参考分词、内存比较和 CSV 写入。两份 ELF 的调用点、返回地址、门入口、B 函数和数据布局均已核对。每个窗口从调用指令退休计到返回 A 后第一条指令退休，按本次配置的 500 ticks/周期换算。[布局与指令检查](../protected/perf_sites.py)

模拟器通过 B 中两条不同指令识别调用路径。读取保存游标表示**传入** NULL；把 token 结果设为零表示**返回** NULL。软件门与硬件门按调用点和该点出现序号逐次配对，分类序列与功能回归交叉核对。[配对方法](../protected/perf_compare.py)

| 调用路径 | 次数 | 软件门周期/次 | 硬件门周期/次 | 节省周期/次 | 节省比例 |
|---|---:|---:|---:|---:|---:|
| 首调，返回 token | 2,174 | 396.90 | 350.02 | 46.88 | 11.81% |
| 续调，返回 token | 6,524 | 413.76 | 364.04 | 49.71 | 12.02% |
| 续调，返回 NULL | 898 | 583.18 | 532.42 | 50.76 | 8.70% |
| **全部** | **9,596** | **425.79** | **376.62** | **49.17** | **11.55%** |

三类路径平均每次节省 47–51 周期。续调返回 NULL 的软件门窗口最长，因此即使每次平均节省 50.76 周期，相对降幅也只有 8.70%。两种计时版均正常退出，`test.out` 和 `test.stderr` 均通过原有 `specdiff`。

| 统计范围 | 软件门周期 | 硬件门周期 | 节省周期（软件减硬件） |
|---|---:|---:|---:|
| 全部调用窗口 | 4,085,911 | 3,614,075 | 471,836 |
| 窗口外 | 33,643,522 | 33,665,768 | −22,246 |
| 完整程序 | 37,729,433 | 37,279,843 | 449,590 |

整程序少退休 777,276 条指令，其中加载和存储各少 230,304 条。折合每次调用少 81 条指令、24 条加载和 24 条存储，与门的指令序列一致。窗口外多用的 22,246 周期抵消了部分窗口内收益，其微架构原因尚未定位。
