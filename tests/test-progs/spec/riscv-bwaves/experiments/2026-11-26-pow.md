# BWaves 中四个 libm `pow` 调用点的寄存器保护开销

2026-11-26，在单线程 RV64 Linux SE、`v5_full` O3 上运行 SPEC CPU2006 `410.bwaves` 的第一个时间步。139,392 次 `pow` 调用的平均窗口从软件门的 343.82 周期降到硬件门的 297.98 周期，**每次节省 45.84 周期（13.33%）**。从程序启动到单步程序退出，共节省 **6,475,390 周期（2.46%）**。节省比例均以对应范围的软件门周期为分母。[双门统计汇总](2026-11-26-pow-summary.json)

## 输入与数值验收

普通 RV64 ELF 中，`shell_` 和 `flux_` 各有一处 `pow(x, 0.75)`，`jacobian_` 有两处，均直接调用同一个 libm 入口。QEMU 完整运行官方 `test` 的 25 个时间步，测得 3,484,800 次调用。`shell_` 和 `flux_` 各 435,600 次，`jacobian_` 两处各 1,306,800 次。`bwaves.out`、`bwaves2.out` 和 `bwaves3.out` 均通过官方 `specdiff`。[调用点识别](../protected/pow_sites.py) · [普通版计数](../protected/ordinary.py)

O3 计时使用相同的 `33 × 33 × 16` 网格、初始条件和隐式求解方法，仅将时间步数由 25 改为 1。普通 ELF 在 QEMU 上运行相同的单步输入，生成三份数值参考。两种门均正常退出，各自的三份输出均与单步参考逐字节一致。下文所有周期均来自单步 O3 运行。[运行与验收](../protected/run_pair.py)

## 调用门与计时边界

两版共用 B 内的 libm 函数体、私有只读查找表和独立栈。`fa0/fa1` 传入双精度参数，`fa0` 返回结果。两种门都保护 `s0–s11/fs0–fs11` 并清零 `t0–t6/ft0–ft6`。软件门用常规指令完成保存、清零和恢复；硬件门执行两条 `PROREG`、两条 `CLR` 和一条 `LEAVE`。[调用门](../protected/gate.S)

B 使用私有浮点环境，进入时清零 `fcsr`，返回时恢复 A 的 `fcsr`。普通版在 25 步和单步运行中均未执行 `pow` 的六个数学异常出口或栈保护失败调用。受保护函数将这些出口重定向到 B 内的失败处理程序，单步测量中该程序的退休次数为零。数值结果覆盖本输入经过的正常计算路径。[受保护函数体](../protected/prepare_body.py)

模拟器在调用者的转移指令退休时开始计时，在返回 A 后第一条指令退休时结束计时，以每周期 500 ticks 换算。两版的对应调用点、门和函数体地址相同，已加载段在寄存器策略区域以外的内容一致（GNU build ID 除外）。按调用点和该点出现序号逐次配对。[布局检查](../protected/pow_sites.py) · [窗口配对](../protected/compare.py)
